# 编辑边界与执行权限

## 当前 CLI 的实际需要

| 路径 | 规划代理直接操作 | 当前 Python 执行器 |
|---|---|---|
| config/plans/ | 读；新增轮次计划与 notes | 读计划 |
| .dsh/skills/、AGENTS.md | 只读 | 按需只读 |
| src/、optimize/、agent_cli.py | 默认不浏览；不修改 | 读取/导入固定代码 |
| config/calibrations/ | 只读 | 只读依赖，不自动发布 |
| result/ | 只读既有实验数据 | 创建新 run、写原始 IQ、manifest、摘要、图；恢复时更新原 run 检查点 |
| config/hardware/ | 只读 | 每次 run 写新硬件快照 |
| 凭据 | 不读取、不输出、不修改 | SDK 使用正常配置；不要把密钥传给模型 |
| 临时目录/缓存 | 不主动修改项目外文件 | 运行时可能需要受控临时目录；可禁写 pycache |

## 两种部署

采用轻量约定时，DSH 只编辑 plans，但其调用的 Python 仍继承相同沙箱权限。
需解决 result/ 和 config/hardware/ 的实际写入权限；仅开放 plans 会使 run 失败。
AGENTS/skills 约束行为，不阻止任意 shell 命令修改已开放目录。
允许任意 Python/shell 或相同身份写目录时，也不具备“仅执行器可写结果”的强制边界。

需要严格隔离时，把受信执行器部署到独立服务/受限工具：
- DSH 仅可写 plans，结果和配置通过只读路径或只读 API 获取。
- 用白名单工具提交计划、查询状态、取消已授权任务、取得结果/摘要。
- 执行器独立校验 schema、文件真实路径及链接、固定代码、用户授权、
  backend/比特/参数硬边界、波形与依赖、单 run 和跨轮次持久预算。
- 在提交前固化计划内容/哈希与授权版本；原子保留总预算，统一处理恢复、重试和不明提交。
- 凭据与受信政策保留在服务侧；只给服务 result/hardware 写权限，
  不给代理任意 shell、服务凭据、可改的受信脚本或调用任意实验代码的能力。

以上服务与硬政策是部署要求，当前项目尚未实现。
不得把安装本 skill 表述为已经实现权限隔离或预算硬约束。

## 已知 DSH 权限问题

当前历史记录显示：根目录有 Low 标签/沙箱授权，已有子目录未获得对应设置，
导致 Low 完整性进程无法写 tests/result 等目录。
按计划操作仍会遇到 result/hardware 写入阻断；skill 不能改变该事实。
向维护者报告准确失败路径，停止硬件提交，不自行运行权限修复脚本。
维护者验证实际创建/保存/恢复成功后再继续。
